# Adam AI Android Professional App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package the exact current Adam AI web application as a production-quality Android app through Capacitor, preserving the existing UI, behavior, data flows, and backend integration instead of creating a second product or a WebView wrapper.

**Architecture:** The existing React/Vite application remains the single source of truth for UI and application behavior. Capacitor supplies the native Android host and build pipeline; Android is generated from the same `dist` output and uses the existing server/API endpoints, authentication, storage, tools, and AI integrations. No redesign or parallel Android feature implementation is introduced.

**Tech Stack:** React 19, TypeScript, Vite, Capacitor 8, Android Gradle Plugin/Gradle, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-29-adam-ai-v2-rebuild-design.md`

## Global Constraints

- The current `main` UI is the visual source of truth and must not be redesigned.
- Android must consume the same built web application rather than a separate Android frontend.
- Existing API, authentication, AI, integrations, local persistence, voice, tools, and settings behavior must remain unchanged.
- `android/` remains generated by Capacitor and is not committed unless the project explicitly changes that policy.
- Provider secrets must not be newly embedded into Android-native source.
- Android packaging must pass TypeScript, tests, web build, Capacitor sync, and Gradle verification.

### Task 1: Align Android CI with the current `main` application

**Files:**
- Modify: `.github/workflows/android-release.yml`

**Interfaces:**
- Input: current `main` source tree and existing npm/Capacitor scripts.
- Output: reproducible Android APK and AAB artifacts built from the same web bundle.

- [ ] Add `npm ci`, `npm run lint`, and `npm test` before packaging.
- [ ] Build the current web application once and run `npx cap sync android` from that output.
- [ ] Build both `assembleDebug` and `bundleRelease`/`assembleRelease` as appropriate for distribution.
- [ ] Verify that the APK exists and that the AAB exists before uploading artifacts.
- [ ] Keep the existing application ID `com.adam.aiagent` and app name `Adam AI Agent`.
- [ ] Preserve the existing release trigger and GitHub artifact/release behavior.
- [ ] Commit the CI change.

## Final verification

Run/inspect the GitHub Actions workflow for the branch and confirm: npm install succeeds, lint/tests/build succeed, Capacitor sync succeeds, debug APK is produced, release APK/AAB packaging succeeds, and artifacts are uploaded. The final Android app must be the current Adam UI and behavior packaged natively, not a redesigned mobile interface or a remote website wrapper.
